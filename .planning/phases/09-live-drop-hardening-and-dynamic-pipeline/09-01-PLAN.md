## 1. Context & Objectives

Currently, when platform adapters fail (e.g., LinkedIn document upload or Threads editor focus), they silently return generic strings like `error="Could not focus Threads post composer editor"`. There is zero visual evidence of what the browser actually saw (DOM state, open modals, error banners), forcing developers to guess CSS selectors in the dark.

Furthermore, testing a fix currently requires running `publish_now.py`, which triggers all 4 platforms simultaneously, wasting time and risking account rate limits.

**Goals:**
1. Add universal visual telemetry in `adapters/base.py`: whenever an adapter encounters an error or returns `success=False`, automatically capture:
   - `shots/{platform}_fail.png` (viewport screenshot)
   - `shots/{platform}_fail.html` (DOM snapshot)
2. Build `scripts/test_adapter.py`: an isolated, single-platform diagnostic CLI tool allowing developers to test and verify any platform in isolation in under 15 seconds.

## 2. Technical Specification

### 2.1 Universal Failure Capture in `adapters/base.py`
Add helper method:
```python
async def capture_failure_artifacts(page: Any, platform: str) -> dict[str, str]:
    """Capture viewport screenshot and DOM dump upon publishing failure."""
    shots_dir = Path("shots")
    shots_dir.mkdir(parents=True, exist_ok=True)
    shot_path = shots_dir / f"{platform}_fail.png"
    html_path = shots_dir / f"{platform}_fail.html"
    try:
        data = await page.send("Page.captureScreenshot", format="png")
        shot_path.write_bytes(base64.b64decode(data["data"]))
    except Exception:
        pass
    try:
        content = await page.eval("document.documentElement.outerHTML")
        if content:
            html_path.write_text(content, encoding="utf-8")
    except Exception:
        pass
    return {"screenshot": str(shot_path), "html": str(html_path)}
```

### 2.2 Diagnostic CLI Tool: `scripts/test_adapter.py`
Create `scripts/test_adapter.py` supporting:
- `--platform <x|bluesky|linkedin|threads>`
- `--text <custom_text>`
- `--media <path_to_media>`
- `--draft <path_to_draft>`
- `--slot <time_slot>`
- `--dry-run`
Executes ONLY the selected adapter, outputs timing and raw responses, and reports captured failure screenshots if errors occur.

## 3. Verification Criteria
1. `python scripts/test_adapter.py --platform bluesky --text "Test diagnostic probe"` verifies Bluesky independently.
2. `python scripts/test_adapter.py --platform linkedin --dry-run` checks LinkedIn session in isolation.
3. If an intentional error is triggered, `shots/{platform}_fail.png` is confirmed written to disk.
