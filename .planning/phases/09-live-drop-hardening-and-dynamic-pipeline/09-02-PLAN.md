## 1. Context & Objectives

In the latest live run, X failed with `[X] FAILED: None`. Root-cause investigation revealed:
1. `shots/compose.png` proved the modal was open, text populated, and card attached.
2. In `scripts/post.py`, `COMPOSE_STATE_JS` only checked `document.querySelector('[data-testid="tweetButton"]')`. In modern modals, the button frequently has `[data-testid="tweetButtonInline"]` or `div[role="button"][data-testid*="tweetButton"]`.
3. Because `btn` was null, `btn_disabled` returned `None`, so `if st.get("btn_disabled") is False:` never matched.
4. `_click_post()` timed out with `"button never enabled"`.
5. `do_post()` discarded this return string, waited 25 seconds for profile indexing (which never happened), and returned `{"posted": False, "verified": False, "error": None}`.
6. `adapters/x.py` reported `error: None`.

**Goals:**
1. Upgrade button detection in `COMPOSE_STATE_JS` and `_click_post` to support all current X button selectors.
2. Synthesize authentic pointer coordinates and click events.
3. Propagate the exact click error to `res["error"]` so errors are never suppressed into `None`.
4. Distinguish between actual submission failure vs. profile timeline indexing delay.

## 2. Technical Specification

### 2.1 Multi-Variant Button Detection in `scripts/post.py`
In `COMPOSE_STATE_JS`:
```javascript
const btn = document.querySelector('[data-testid="tweetButton"]')
  || document.querySelector('[data-testid="tweetButtonInline"]')
  || document.querySelector('button[data-testid*="tweetButton"]')
  || document.querySelector('div[role="button"][data-testid*="tweetButton"]');
```

### 2.2 Error Surface in `scripts/post.py::do_post`
```python
click = await _click_post(page)
if click != "clicked":
    return {
        "posted": False,
        "verified": False,
        "error": f"Post button click failed: {click}",
        "screenshot": str(shot),
    }
```

### 2.3 Explicit Error Reporting in `adapters/x.py`
Ensure `res.get("error")` captures the click error, and if submission succeeded but timeline readback timed out, report `verified=False` without marking the post as an outright crash if the toast was detected.
