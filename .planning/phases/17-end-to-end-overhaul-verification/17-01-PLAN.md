<task type="auto">
  <name>Task 1: Build the overhaul verifier</name>
  <files>scripts/verify_overhaul.py</files>
  <read_first>scripts/errors.py, scripts/publish_now.py, scripts/doctor.py, scripts/ledger.py, scripts/repurpose.py, render/cards.py</read_first>
  <action>
Create `scripts/verify_overhaul.py` with a `main()` and a `run_checks(dry_run: bool = True, render: bool = False) -> dict` API. It must check:
1. Relevance: the Kushner political item is rejected; a Postgres/latency item is accepted.
2. Fail-closed synthesis: a title-only item raises `TopicRejected`.
3. Uniqueness: two topics produce different bullet sets; duplicate fingerprints are rejected.
4. State truth: success+verified false maps to `submitted_unverified`; only verified satisfies done.
5. Limits: X/Bluesky/Threads/LinkedIn counts are within min/max; emoji and CJK fixtures pass.
6. Render (only when `--render`): generated cards are 1080x1920 at scale 1 and 2160x3840 at scale 2; template has no remote font; offline render works. The static checks must run without a browser.
7. Media contract: LinkedIn carousel payload has a PDF and `media_type="carousel"`; image payload has no document title.
8. Duplicate safety: a repeated idempotency key is skipped.

Output JSON with `checks: [{name, status, detail}]`, `overall: PASS|FAIL`, and `generated_at`. Exit 0 only when every requested check passes.

Define these CLI flags in Task 1: `--dry-run` (default), `--two-topic`, `--render`, `--report PATH`, `--source live|dry-run`, `--slot HH:MM` (default `09:00`), `--live`, and `--confirm-live`. `--live` must require an explicit `--confirm-live` token so it cannot run accidentally. `--slot` accepts the same `HH:MM` format as `publish_now.py`; do not use a bare slot number.
  </action>
  <verify>python -m py_compile scripts/verify_overhaul.py; python scripts/verify_overhaul.py --dry-run</verify>
  <acceptance_criteria>
    - Static dry-run checks run without network or browser.
    - The render check is opt-in via `--render` and requires a browser.
    - Every acceptance criterion has a named check.
    - Exit code is non-zero on any failed check.
    - `--slot` accepts `HH:MM`; `--report`, `--two-topic`, and `--render` are defined.
    - `--live` requires explicit confirmation.
  </acceptance_criteria>
  <done>There is one machine-readable acceptance gate for the overhaul.</done>
