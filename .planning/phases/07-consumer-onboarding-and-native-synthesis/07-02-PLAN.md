## 1. Context & Objectives

Currently, `scripts/generate.py` synthesizes one core post draft. When published across 4 platforms, `scripts/publish_now.py` mechanically slices the text at platform character limits with trailing ellipses (`...`). This destroys engagement on X and Bluesky, while producing posts that are far too brief and informal for LinkedIn.

**Goal:**
1. Upgrade `scripts/generate.py` and `scripts/llm.py` to generate 4 distinct, platform-tailored variations in a single structured JSON response from the user's selected LLM.
2. Enforce audience engagement archetypes:
   - **X (Twitter):** 180–260 chars, 1-line contrarian hook, compact line breaks, 0 hashtags.
   - **LinkedIn:** 600–1,200 chars, attention-grabbing opening, mobile whitespace, 3-point framework, plus 4-slide PDF carousel metadata.
   - **Threads:** 250–420 chars, conversational community tone, ends with an engagement question to trigger reply algorithms.
   - **Bluesky:** 160–270 chars, direct, witty, anti-hype, tech-insider tone.
3. Update `scripts/publish_now.py` and adapters to consume tailored text per channel, completely eliminating arbitrary string slicing.

---

## 2. Technical Specification

### 2.1 Unified 4-Platform Prompt Contract
In `scripts/generate.py`, build a structured prompt instructing the LLM to output valid JSON:
```json
{
  "x": "Punchy 1-2 liner under 280 characters with immediate hook and sharp insight. No hashtags.",
  "bluesky": "Direct, conversational tech take under 300 characters.",
  "threads": "Casual community discussion starter ending with an engaging question (<500 chars).",
  "linkedin": "Compelling narrative hook, 3 structured takeaways with clean whitespace, and concluding takeaway (<1500 chars).",
  "carousel": {
    "title": "Topic Framework",
    "slides": [
      {"header": "Problem / Reality", "body": "..."},
      {"header": "Rule 1", "body": "..."},
      {"header": "Rule 2", "body": "..."},
      {"header": "Rule 3 / Takeaway", "body": "..."}
    ]
  }
}
```

### 2.2 Integration with Voice Profile
- Incorporate `voice.json` style constraints into the prompt (e.g. banned buzzwords, tone directives, sentence rhythm).
- If the LLM call fails or is unconfigured, provide a deterministic heuristic generator that produces compliant tailored mock drafts for all 4 platforms.

### 2.3 Adapter & Carousel Pipeline Synchronization
- When `render/carousel.py` generates a PDF from the `carousel` metadata, attach it automatically to the LinkedIn publishing payload.
- Update `scripts/publish_now.py` to check `payload.platforms[plat_key]` and select the channel-specific text rather than relying on a single uniform `payload.text`.

## 3. Target File Modifications

- `scripts/llm.py`:
  - Enhance structured JSON parsing to validate presence of `"x"`, `"bluesky"`, `"threads"`, `"linkedin"`, and `"carousel"`.
- `scripts/generate.py`:
  - Implement `generate_platform_native_drafts(topic: str, context: str, voice_profile: dict) -> dict`.
  - Update heuristic generator to produce 4 channel-specific drafts when LLM is unavailable.
- `scripts/publish_now.py`:
  - Consume platform-specific text from draft/payload.
  - Remove destructive `text[:limit-3] + '...'` slicing for supported platform drafts.
- `tests/test_generate.py` & `tests/test_llm.py`:
  - Unit tests validating JSON extraction of all 4 platform drafts and carousel slide structure.
  - Tests ensuring character caps are respected per platform.

---

## 4. Verification & Acceptance Criteria

1. Running draft generation produces 4 distinctly formatted variations from a single topic.
2. X post is strictly < 280 chars with no trailing hashtags.
3. Threads post ends with an engagement question.
4. LinkedIn post includes structured bulleted takeaways and carousel slide data.
5. `publish_now.py` publishes each platform's native text without truncating ellipses.
6. All tests in `tests/test_generate.py` and `tests/test_llm.py` pass 100%.
