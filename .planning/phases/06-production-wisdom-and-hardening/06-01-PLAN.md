## 1. Context & Objectives

OmniPost has strong technical foundations (atomic ledger, crash recovery, CDP adapters), but currently lacks the strict, enforcement-first guard rails that make TweetyTweets safe in production. In autonomous publishing, a single bad post (engagement bait, fabricated statistics, duplicate text, wrong account handle, or unverified limits) damages credibility or triggers platform spam filters.

**Goal:** Implement an enforcement-first guard rail system in code (`scripts/validator.py`, `scripts/due.py`, `scripts/post.py`, and `scripts/research.py`) that strictly rejects unverified drafts before they can ever reach the browser or API publishing pipelines.

---

## 2. Hard Rules Specification

We introduce the **OmniPost Hard Rules Doctrine**:
1. **Measured Character Ceiling**: Never hardcode or assume character limit ceilings. If character limits have not been measured and saved via `post.py measure --save` (or verified in config), abort with `GuardRailError`.
2. **Zero Engagement Bait**: Explicitly forbid patterns like "thoughts?", "agree?", "like if", "retweet", "comment below", "share this post", "follow for more". These are flagged by social platform algorithms as spam.
3. **Read Before You Write (Hard Rule 3b)**: Every post claim must trace to a source URL/item collected in `research.py` or local swipe files. Reject drafts containing fabricated citations or unverified statistical claims.
4. **Zero Duplicate Content**: Never publish identical text twice. Compare candidate drafts against all past posts in `state.json` using exact match and normalized hash.
5. **Absolute Handle Guard**: Refuse publishing if the browser or session handle does not strictly match the configured account handle.
6. **Account Warm-Up Guard**: If an account has fewer than 15 recorded posts or is under 14 days old in the ledger, cap automation at 1 post/day and emit an account warm-up safety warning.

## 3. Target File Modifications

- `scripts/validator.py`:
  - Define `GuardRailError(Exception)` and specific subtypes (`CharacterLimitNotMeasuredError`, `EngagementBaitError`, `FabricatedClaimError`, `DuplicatePostError`, `HandleMismatchError`).
  - Implement `validate_draft_guardrails(draft: dict, config: dict, state: dict) -> tuple[bool, list[str]]`.
  - Implement `engagement_bait_pattern_detected(text: str) -> tuple[bool, str]`.
  - Implement `verify_character_ceiling_measured(platform: str, config: dict) -> bool`.
  - Implement `check_duplicate_post(text: str, state: dict) -> bool`.
  - Implement `verify_source_trace(draft: dict, research_dir: Path) -> tuple[bool, str]`.

- `scripts/post.py` & `adapters/base.py`:
  - Enforce `validate_draft_guardrails` before any post action.
  - Implement `post.py measure --save` command to measure real platform character limit live in the browser and record it to `state.json` / `config.json`.
  - Enforce handle verification matching against configured target handle before submitting DOM forms.

- `scripts/due.py`:
  - Call `validate_draft_guardrails` during `due.py check` so invalid drafts are surfaced as blocked rather than silently queued.
  - Implement warm-up rate throttling if ledger indicates new account.

- `scripts/research.py`:
  - Add source provenance metadata (`source_url`, `retrieved_at`, `source_type`) to all saved items so downstream draft generators can cite verified origins.

- `tests/test_guardrails.py` (New):
  - Comprehensive unit tests verifying that all 6 hard rules reject invalid content and pass compliant content.

## 4. Implementation Steps

### Task 1: GuardRailError Hierarchy and Validation Routines (`scripts/validator.py`)
- Create `GuardRailError`, `EngagementBaitError`, `FabricatedClaimError`, `DuplicatePostError`, `CharacterLimitNotMeasuredError`.
- Build regex and heuristic detectors for engagement bait phrases.
- Build duplicate post hash detector comparing against `state.json` post history.
- Build source trace validation checking draft provenance against `research.py` output.

### Task 2: Live Character Ceiling Measurement in `scripts/post.py`
- Add CLI command `python scripts/post.py measure --save` which drives CDP to binary-search or test the platform character limit in the composer and records `verified_character_ceiling` in `state.json`.
- In `post.py post` and adapter publish methods, require `verified_character_ceiling` or explicit bypass flag.

### Task 3: Account Warm-Up Safety Throttling in `scripts/due.py`
- Read `state.json` post history.
- Calculate account age and total verified posts.
- If under 14 days or < 15 posts, enforce max 1 slot per day and log warm-up advisory.

### Task 4: Unit Test Suite (`tests/test_guardrails.py`)
- Test engagement bait rejection ("What are your thoughts? Agree?").
- Test duplicate post rejection against state ledger.
- Test unmeasured character ceiling rejection.
- Test handle mismatch rejection.
- Test warm-up throttling logic.
