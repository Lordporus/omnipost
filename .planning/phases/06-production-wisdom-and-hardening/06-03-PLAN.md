## 1. Context & Objectives

OmniPost has 153 passing unit tests and comprehensive features, but is missing two essential qualities that make production open-source software trustworthy:
1. **Real-World End-to-End Test Suite**: Current tests heavily mock isolated functions. We need end-to-end integration tests that validate the full pipeline: dry-run compose -> adapter routing -> ledger update -> read-back verification, actual carousel PDF structure and DOM payload generation, and polymorphic multi-platform content adaptation invariants.
2. **Brutal Risk Honesty & Documentation Depth**: TweetyTweets sets the gold standard for transparency. It explicitly warns users that browser automation violates platform terms of service, accounts can be suspended, vision models hallucinate numbers, and DOM selectors break when platforms update. Furthermore, its documentation offers a unified journey (Step 0: The Interview -> Step 1: Supervised Post -> Step 2: Automation) and shares 10 "Pitfalls Already Paid For".

**Goal:** Create an E2E integration test suite and overhaul `README.md`, `USERGUIDE.md`, and `SKILL.md` with honest risk sections, "Pitfalls Already Paid For", a documented minimal-dependency philosophy (3 deps only), and account safety warm-up protocols.

## 2. Technical Scope & Architecture

### A. E2E Integration Test Suite
1. `tests/test_integration_e2e.py`:
   - Validates the end-to-end execution path: reading a mock research item -> generating polymorphic drafts -> running through all 4 platform adapters in dry-run mode -> recording results to `state.json` v2.0 -> executing read-back verification checks.
2. `tests/test_carousel_rendering.py`:
   - Validates multi-slide PDF carousel rendering via `render/carousel.py`.
   - Inspects generated PDF binary bytes for valid `%PDF` headers, page count match, 1080x1080 aspect ratios, and simulated LinkedIn document upload payload validation.
3. `tests/test_multiplatform_adaptation.py`:
   - Takes 1 core research insight and runs `scripts/repurpose.py`.
   - Verifies simultaneously:
     - X draft adheres to concise character limit and hook styling.
     - Bluesky draft respects 300 UTF-8 character limit and calculates valid byte facets for links.
     - LinkedIn draft features professional spacing, bold key takeaways, and document attachment metadata.
     - Threads draft stays within 500 characters and features punchy paragraph breaks.

### B. Transparency & Risk Honesty Overhaul (`README.md` & `USERGUIDE.md`)
- Add a prominent **"Risks & Limitations"** section:
  - **Account Safety & Terms of Service**: Browser automation on X, LinkedIn, and Threads operates in a grey zone and violates platform automation policies. Accounts can be rate-limited, shadowbanned, or permanently suspended.
  - **Account Warm-Up Requirement**: New accounts publishing high-frequency automated content look identical to spam botnets. Warm up accounts manually for 14 days before automating.
  - **Vision Model Trust Boundaries**: Vision models (GPT-4o, Claude 3.5 Sonnet, Gemini Flash) are great for semantic layout inspection but **unreliable for numbers, timestamps, and subtle UI badges**. Never rely on vision for numerical verification.
  - **DOM Fragility & Selector Drift**: Social networks change their web clients frequently. When LinkedIn or X updates its DOM, selectors degrade. OmniPost isolates failures, but human maintenance of selectors is inevitable.
  - **Scope Boundaries**: OmniPost is strictly for **publishing**. Automating replies, likes, follows, or DMs is banned and leads to immediate account termination.

### C. "Pitfalls Already Paid For" (10 Hard-Won Lessons)
Add documented lessons to `README.md` and `SKILL.md`:
1. CDP WebSocket Drops: Remote Chrome instances drop connections during heavy DOM re-renders; keep retries bounded.
2. ProseMirror Synthetic Events: Plain DOM `.value = ...` does not work on modern web composers; require CDP `Input.insertText`.
3. Stealth Evasion Detection: Simply passing `--remote-debugging-port` leaks automation flags without navigator webdriver overrides.
4. Stale Timeline Rendering: Social feeds cache aggressively; read-back verification must inspect author profile activity, not home feeds.
5. PDF Carousel Viewport Scaling: `Page.printToPDF` requires precise CSS `@page` dimension locking to avoid blurred 1080x1080 slides.
6. Rate Limit Cooldown Windows: LinkedIn requires a minimum 4-hour gap between posts; consecutive posts trigger account lock.
7. Atomic Ledger State Locks: Race conditions during cron runs corrupt JSON files without file locking or atomic rename patterns.
8. Zero-Cost Idle Suppressions: Polling LLM agents every 10 minutes wastes hundreds of dollars if un-gated; gate scripts must output byte-identical `IDLE`.
9. The "Read Before You Write" Invariant: AI models hallucinate facts unless strictly anchored to scraped research text.
10. The Voice Drift Trap: AI models inevitably drift towards corporate cheerleading unless constrained by an active "DO-NOT" list.

### D. Minimal Dependencies Philosophy (3 Dependencies)
- Highlight the intentional zero-bloat philosophy:
  - `websockets >= 12.0`: Direct Chrome DevTools Protocol communication (no Selenium, Playwright, or Puppeteer bloat).
  - `Pillow >= 10.0.0`: Pure visual rendering for infocards (no Cairo, no ImageMagick, no Node canvas).
  - `pyyaml >= 6.0`: Configuration and docker compose validation.
  - Total external dependencies: **3**. Standard library for everything else. Cost of adding an adapter: **0 dependencies**.
