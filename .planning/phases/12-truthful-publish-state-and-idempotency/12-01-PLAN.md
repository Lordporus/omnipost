<objective>
Make publishing state truthful and idempotent. Replace the binary published/failed status with verified/unverified/failed, serialize state updates across processes, cancel timed-out workers and reconcile them, and require an idempotency key before dispatch.

Purpose: The live run recorded Threads as PASS while verification was false, and the timeout path can record failure after a post already landed. Both produce missing posts or duplicates.

Output: a migrated `scripts/ledger.py`, a killable `scripts/publish_worker.py`, a dedupe-aware `scripts/publish_now.py`, and state/idempotency tests.
</objective>

<task type="auto">
  <name>Task 3: Replace the fake timeout with a killable worker and reconciliation</name>
  <files>scripts/errors.py, scripts/publish_worker.py, scripts/publish_now.py, adapters/base.py</files>
  <read_first>scripts/publish_now.py, scripts/ledger.py, scripts/errors.py, adapters/base.py</read_first>
  <action>
Create `scripts/publish_worker.py`:
- Read a JSON object from stdin: `{platform, text, media_paths, media_type, extra_metadata}`.
- Resolve the adapter via `settings.get_active_adapters()` and call `publish`.
- Write the result to a temp file passed via `--result-file`, not stdout. Adapters may print to stdout (Threads does), so stdout is not a safe JSON channel. Write `{success, verified, url, post_id, error, raw_response}` to the file atomically.
- Redirect adapter stdout to stderr (or leave it; the result file is authoritative). Exit non-zero on an unhandled exception; include the exception type/message in stderr.

Update `scripts/publish_now.py`:
- Replace the `ThreadPoolExecutor` block with `subprocess.Popen([sys.executable, "-m", "scripts.publish_worker", "--result-file", str(result_path)], stdin=PIPE, stdout=PIPE, stderr=PIPE, text=True)` and `communicate(timeout=args.timeout)`.
- On timeout: `proc.kill()`, wait, then call `adapter.verify(None, post_text[:80])` to reconcile. If verification succeeds, record `published_verified`; if it fails, record `submitted_unverified` with `error="timeout_unreconciled"` and do not auto-retry. Never record `failed` solely because the client timed out.
- On non-zero exit or missing/invalid result file, record `failed` with the captured stderr.
- Preserve the existing per-platform output and webhook dispatch.

Add `idempotency_key` to the platform status record and store `f"{date}:{slot}:{platform}"`. Add `reserve_idempotency(key, platform, force=False, allow_failed=False)` to `ledger.py`. It must open its own `state_transaction`, reload state, and:
- if the key exists and `force=False` and `allow_failed=False`, return False;
- if the key exists with status `failed` and `allow_failed=True`, increment `attempt` and write a fresh `pending` reservation;
- if the key exists and `force=True`, increment `attempt` and overwrite the reservation with a fresh `pending` record;
- otherwise write a `pending` record with `reserved_at`, `pid`, and `attempt=1`, then return True.

`submitted_unverified` is never auto-retried; only `failed` may be retried when the caller explicitly enables `allow_failed`.

The function owns the transaction; callers must NOT call it inside another `state_transaction` (that would self-deadlock on `msvcrt.locking`/`fcntl.flock` and could save stale state). The reservation is committed before dispatch, so two processes cannot both pass a read-only check and publish.
  </action>
  <verify>python -m py_compile scripts/publish_worker.py scripts/publish_now.py; python -c "from scripts import ledger; assert hasattr(ledger, 'reserve_idempotency'); print('ok')"</verify>
  <acceptance_criteria>
    - A timed-out worker process is killed; no worker survives the timeout.
    - Reconciliation runs before status is recorded.
    - A reconciled post is not retried automatically.
    - The worker writes valid JSON to the result file even when an adapter prints to stdout.
    - The idempotency reservation is written before dispatch, not after.
  </acceptance_criteria>
  <done>Timeouts are real cancellations and cannot silently create duplicates.</done>

After a successful reservation, reload state before dispatch so the caller does not hold a stale copy.
