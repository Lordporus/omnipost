## 1. Context & Objectives

In OmniPost V1, `state.json` tracked posts under a single-platform model (`tweet_url`, `verified: true`). In V2, OmniPost posts to up to four platforms simultaneously: **X**, **Bluesky**, **LinkedIn**, and **Meta Threads**.

When publishing a due slot across 4 networks:
1. Network transients, cooldowns (e.g. LinkedIn 4h gap), or rate limits can cause 1 platform to fail while the other 3 succeed.
2. Currently, if `autoposter.py` marks the slot as `posted` via `due.py mark`, the failed platform is **never retried**.
3. Conversely, if `autoposter.py` does not mark the slot, the next cron tick **double-posts** to the 3 platforms that already succeeded.

**Goal:** Implement a Schema v2.0 State Ledger (`scripts/ledger.py`) and upgrade `scripts/autoposter.py` and `scripts/due.py` so that publication status is tracked atomically *per-platform* for every slot. Any partial failure will safely isolate the failed channel and retry **only** the failed platform on subsequent ticks, with 0% risk of duplicate posting.

## 2. Target File Modifications

- `scripts/ledger.py` (New): Central state manager for `state.json` v2.0 schema, atomic read/write, legacy v1.0 auto-migration, and per-platform slot query APIs.
- `scripts/due.py` (Modified): Update `_posted_slots()`, `due()`, `show`, and `mark` to evaluate per-platform ledger status.
- `scripts/autoposter.py` (Modified): Check ledger prior to publishing each platform; skip already published/verified platforms; record results atomically per-platform; leave slot pending if any platform failed.
- `tests/test_ledger.py` (New): Unit tests for v1-to-v2 migration, per-platform recording, and idempotency.
- `tests/test_retry_isolation.py` (New): Unit tests simulating partial network failure, verified skip of already-posted platforms, and clean retry of failed channels.

### Backward Compatibility (V1 Migration)
Any legacy post record structured as:
```json
{
  "at": "2026-10-04T12:53:16.000Z",
  "slot": "13:00",
  "tweet_url": "https://x.com/...",
  "verified": true
}
```
will be seamlessly loaded and represented in-memory as:
```json
"platforms": {
  "x": {
    "status": "published",
    "url": "https://x.com/...",
    "verified": true,
    "at": "2026-10-04T12:53:16.000Z",
    "error": null
  }
}
```
Existing user post history in `state.json` will be safely preserved with zero data loss.

## 4. Implementation Steps

### Step 1: Create `scripts/ledger.py`
Provide clean, atomic helper functions:
* `load_state() -> dict`: Reads `state.json`, runs migration if `version != "2.0"`, returns standardized dict.
* `save_state(data: dict) -> None`: Atomic write using temp file replacement.
* `get_slot_entry(date: str, slot: str) -> dict | None`: Looks up post record by date and slot.
* `is_platform_done(date: str, slot: str, platform: str) -> bool`: Returns `True` if platform status is `"published"` and `verified is True`.
* `record_platform_status(date: str, slot: str, platform: str, result: PublishResult, text: str = "", kind: str = "value") -> None`: Atomically updates or creates the slot entry.
* `is_slot_fully_published(date: str, slot: str, target_platforms: list[str]) -> bool`: Returns `True` only if every targeted platform is `"published"` and verified.

### Step 2: Upgrade `scripts/autoposter.py` for Partial-Failure Isolation
1. Before publishing a due slot, inspect `target_platforms = [p for p in active_platforms if plat_draft_enabled]`.
2. For each `platform` in `target_platforms`:
   * Call `ledger.is_platform_done(date, slot, platform)`.
   * If already done: Log `[SKIP] [{platform.upper()}] Slot {slot} already published ({url}). Skipping to prevent duplicates.`
   * If not done: Run `adapter.publish(payload)`.
3. Record each platform result immediately via `ledger.record_platform_status()`.
4. After attempting all platforms:
   * If `ledger.is_slot_fully_published(date, slot, target_platforms)`:
     - Mark draft slot `posted = True` in `drafts/YYYY-MM-DD.json`.
     - Log `[SUCCESS] Slot {slot} fully published across all target platforms.`
   * If any platform failed:
     - Keep draft slot `posted = False` in `drafts/YYYY-MM-DD.json`.
     - Log `[PARTIAL] Slot {slot} partially published. Remaining failed channels will be retried on next tick.`

### Step 3: Upgrade `scripts/due.py`
1. Update `_posted_slots()` to consult `ledger.is_slot_fully_published()`.
2. Update `due()` so a slot with partially failed channels remains eligible for scheduled retries.
3. Update `show` CLI command to render a per-platform publishing grid:
   `13:00  value      due 13:12  [X: OK | BSKY: OK | LINKEDIN: FAIL | THREADS: OK]`
