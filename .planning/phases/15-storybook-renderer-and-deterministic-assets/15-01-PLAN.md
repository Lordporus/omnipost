<objective>
Replace the fixed 1080x1080 generic card engine with a 1080x1920 topic-driven storybook renderer. Embed fonts, wait for real readiness instead of sleeping, derive every slide from the topic, and fail loudly when an asset cannot be produced.

Purpose: The live card repeated the same fallback sentence and used a 1:1 canvas with hardcoded slides 2-3. That is the visible proof that the content engine and renderer are disconnected.

Output: a rewritten `render/card_template.html`, a topic-driven `render/cards.py`, vendored fonts, a fail-hard repurposer, and golden tests.
</objective>

- Replace `await asyncio.sleep(1.2)` with a readiness wait:
  ```python
  await page.send("Runtime.evaluate", expression="""
    (async () => {
      await document.fonts.ready;
      await Promise.all(Array.from(document.images).map(img => img.decode().catch(() => {})));
      await new Promise(r => requestAnimationFrame(() => requestAnimationFrame(r)));
      return true;
    })()
  """, awaitPromise=True, returnByValue=True)
  ```
  Add a bounded retry/timeout (for example 10 seconds) and raise `RenderError("capture_not_ready")` if it fails.
- Return `True` only after the PNG is written; raise `RenderError` with the output path and CDP error when capture fails.
- Remove the `except Exception: count = 2` clamp in `generate_topic_cards`; let `determine_card_count` errors surface.
  </action>
