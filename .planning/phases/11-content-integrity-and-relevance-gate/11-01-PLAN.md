<objective>
Stop the content engine from publishing off-topic, repetitive, boilerplate posts. Add a deterministic relevance gate, make generation fail closed when a source has no usable summary, derive all bullets/takeaways from the topic, remove hardcoded LinkedIn copy, and enforce cross-slot uniqueness.

Purpose: The live draft proves that unrelated HN headlines become AI-architecture posts with identical bullets. Fixing the renderer or adapters without fixing this still produces professional-looking AI slop.

Output: `scripts/relevance.py`, a fail-closed `scripts/generate.py`, a topic-derived `scripts/repurpose.py`, pipeline rejection handling, config defaults, and `tests/test_content_integrity.py`.
</objective>

Create `scripts/relevance.py` with:
```python
def score_item(item: dict, config: dict | None = None, voice_profile: str | None = None) -> RelevanceResult
def score_candidates(items: list[dict], config: dict | None = None, voice_profile: str | None = None) -> list[tuple[dict, RelevanceResult]]
```
`RelevanceResult` must expose `accepted: bool`, `score: int`, `reasons: list[str]`, `matched_terms: list[str]`, and `voice_alignment: int`.

Implement deterministic scoring over `title`, `summary`/`extra.summary`, and `url`:
- Normalize to lowercase and tokenize on non-alphanumerics.
- Strong engineering taxonomy terms include: ai, llm, agent, agents, model, inference, training, transformer, rag, embedding, vector, kubernetes, docker, container, database, postgres, sqlite, distributed, concurrency, latency, throughput, reliability, observability, compiler, rust, python, typescript, api, architecture, state machine, queue, retry, deployment, security.
- Weak terms include: engineering, production, system, scale, performance, design, code, software.
- Reject immediately if the title or summary matches the blocklist: politics, election, president, trump, kushner, celebrity, sports, movie, music, crypto price, stock price, weather, crime, war, and similar general-news markers. Keep the blocklist in `config.example.json` under `content.relevance.blocklist`.
- Accept only when the score meets `content.relevance.min_score` (default 2 strong hits, or 1 strong + 2 weak hits). An item with zero strong terms is rejected.
- If `voice_profile` is supplied, extract its topic nouns/keywords and add `+1` to `voice_alignment` for each overlap (capped at 3). Do not let a voice match override a blocklist rejection.
- `config=None` must load `settings.load().get("content", {}).get("relevance", {})` and fall back to the built-in defaults, so a project without the block still gets the gate.
- Return reasons such as `"blocklist:politics"`, `"score:3"`, `"no_engineering_terms"`, `"voice:2"`.

Add a `content` block to `config.example.json`:
```json
"content": {
  "relevance": {
    "min_score": 2,
    "blocklist": ["politics", "election", "president", "trump", "kushner", "celebrity", "sports", "movie", "music", "crypto price", "stock price", "weather", "crime", "war"],
    "taxonomy_strong": ["ai", "llm", "agent", "model", "inference", "kubernetes", "docker", "database", "distributed", "latency", "reliability", "observability", "compiler", "rust", "python", "typescript", "api", "architecture", "queue", "retry", "deployment", "security"],
    "taxonomy_weak": ["engineering", "production", "system", "scale", "performance", "design", "code", "software"]
  }
}
```

Do not add a network or LLM dependency. Do not reject a valid engineering item merely because it mentions a blocked word in a quoted context; match whole tokens, not substrings.

Create `scripts/errors.py` with the shared content errors:
```python
class ContentError(Exception): ...
class TopicRejected(ContentError):
    def __init__(self, reason, item=None): ...
class NoRelevantTopic(ContentError): ...
class DuplicateTopic(ContentError): ...
```
Import these in `generate.py` and `pipeline.py`; do not define a second `TopicRejected` in `generate.py`.

In `scripts/generate.py`:
- Delete the block that synthesizes `"Analyzing architectural tradeoffs, latency considerations, and state machine reliability for {title} in production systems."`.
- Before synthesis, require a usable summary: `summary.strip()` must be at least 40 characters, must not equal the title, and must not be only the title plus punctuation. If it fails, raise `TopicRejected("missing_summary", item)`.
- Delete `fallback_defaults` from `extract_key_takeaways`. Return only topic-grounded points. If fewer than 3 points are available after extraction, derive additional points from distinct sentences/key phrases in the summary. If still fewer than 3, raise `TopicRejected("insufficient_takeaways", item)`.
- In `generate_topic_from_items`:
  - If `items` is empty, raise `NoRelevantTopic("no_items")`; do not generate a heuristic topic from an empty list.
  - Call `score_candidates(items, voice_profile=voice_profile)`, keep only accepted items, and sort by score descending. If none pass, raise `NoRelevantTopic` with the rejection reasons.
  - Use the highest-scoring accepted item as the source for both the heuristic and LLM paths.
  - If the LLM path returns `ok=True`, validate the returned topic's headline/body against the source item with `score_item` and reject a topic whose text is off-topic or blocklisted.
  - If the LLM path returns `ok=False`, do not accept `llm.generate_topic_with_llm`'s heuristic fallback blindly. Either use `generate_heuristic_topic` on the accepted source item and gate the result, or raise `TopicRejected("llm_failed")`. Remove the unconditional fallback return in `scripts/llm.py` so it returns `(False, None)` on failure instead of a topic that bypasses the gate.
- Set `takeaway` from `topic_data.get("takeaway")` if present, otherwise the last grounded point. Never use `domain`, `source_name`, or the literal `"Verified Reference"`.
- Keep the existing return contract: `headline`, `body`, `points`, `takeaway`, `category`, and the per-platform `platforms` dict.

In `scripts/pipeline.py`:
- Load the voice profile once per run from `references/voice-profile.local.md` using `scripts/voice_profile.py` (if the file exists) and pass it as `voice_profile=` to every `generate_topic_from_items` call. A missing profile is allowed, but a present profile must reach the relevance gate.
- Wrap per-slot generation in a loop over candidate items. On `TopicRejected`, log the item title and reason, remove it from the candidate list, and try the next item.
- If no candidate survives for a slot, raise a `NoRelevantTopic` error that names the date/slot and the rejection reasons. Do not write a draft with placeholder content.
- Do not catch `TopicRejected` and substitute a hardcoded fallback topic.
  </action>

    - `scripts/generate.py` contains no `"Analyzing architectural tradeoffs"` string.
